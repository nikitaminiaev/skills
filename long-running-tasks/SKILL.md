# Long-running tasks

## Порог

Команда может идти дольше ~5 минут → запускай фоном. В foreground — только короткие команды.

## Запуск

Основной способ — detached tmux-сессия с маркером завершения:

```bash
tmux new-session -d -s task 'CMD && echo "DONE $(date +%s)" >> /tmp/task.log || echo "FAIL $(date +%s)" >> /tmp/task.log'
```

Если tmux не установлен — nohup fallback:

```bash
nohup bash -c 'CMD && echo "DONE $(date +%s)" >> /tmp/task.log || echo "FAIL $(date +%s)" >> /tmp/task.log' > /dev/null 2>&1 &
echo $! > /tmp/task.pid
```

## Адаптивное ожидание

1. Оцени длительность: скачивание — размер по `curl -I` / скорость; прочее — по логу, стадиям, прошлому опыту.
2. `sleep min(оценка, потолок_мин)` — потолок выбирай под задачу (60/120/500 мин), без привязки к фиксированному числу.
3. Проверь прогресс:
   - `grep -E 'DONE|FAIL' /tmp/task.log` → завершено
   - иначе: `tail -20 /tmp/task.log`, размер артефакта (`wc -c`), оцени сколько сделано.
4. Не завершено → переоцени оставшееся время по прогрессу за прошедший sleep (экстраполяция), снова sleep, повторяй.
5. Потолок итераций: суммарно не более N попыток; упёрся → доложи о зависании с tail лога, не крути цикл вечно.

## Верификация результата

- DONE → хвост лога + артефакт: размер файла vs ожидаемый, контрольная сумма если известна; для сборки/миграции — ключевые строки успеха.
- FAIL → прочитай лог, найди причину, доложи.
- Нет ни DONE, ни FAIL после потолка → зависание, доложи с tail.

## Завершение

- Убери tmux-сессию: `tmux kill-session -t task` (если была).
- Отчитайся фактами: маркер, время, размер артефакта, ключевые строки лога.
