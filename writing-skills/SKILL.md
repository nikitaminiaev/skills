# Как писать скиллы для opencode

Руководство по созданию скиллов, резюмирующее официальную документацию
(https://opencode.ai/docs/skills) + практический опыт.

## Что такое скилл

SKILL.md-определение переиспользуемого поведения. Скиллы загружаются **по требованию**
через нативный инструмент `skill`: агент видит список доступных скиллов (имя + описание),
а полное содержимое подгружается в контекст только когда агент вызывает `skill`.

## Где размещать файлы

Один скилл = одна папка, внутри обязательно `SKILL.md` (все капсом).

Места поиска (перечислены по приоритету для проекта):
- Проект: `.opencode/skills/<name>/SKILL.md`
- Глобально: `~/.config/opencode/skills/<name>/SKILL.md`
- Claude-совместимо: `.claude/skills/<name>/SKILL.md` и `~/.claude/skills/<name>/SKILL.md`
- Agents-совместимо: `.agents/skills/<name>/SKILL.md` и `~/.agents/skills/<name>/SKILL.md`

## Как происходит discovery

Для проектных путей opencode идёт вверх от текущей рабочей директории до корня git-worktree
и подхватывает все `skills/*/SKILL.md` в `.opencode/`, `.claude/skills/`, `.agents/skills/` на пути.
Глобальные скиллы грузятся из `~/.config/opencode/skills/` и аналогичных.

## Frontmatter (обязательный)

Каждый `SKILL.md` должен начинаться с YAML frontmatter. Признаются только поля:

- `name` (обязательно)
- `description` (обязательно)
- `license` (опционально)
- `compatibility` (опционально)
- `metadata` (опционально, карта string→string)

Неизвестные поля игнорируются. Имя скилла в frontmatter **должно совпадать с именем папки**.

## Правила имени (name)

- 1–64 символа
- lowercase alphanumeric, разделитель — одиночный дефис
- не начинается и не заканчивается на `-`
- без подряд идущих `--`
- совпадает с именем директории, содержащей `SKILL.md`

Regex: `^[a-z0-9]+(-[a-z0-9]+)*$`

## Правила описания (description)

- 1–1024 символа
- Специфичное и точное: агент выбирает скилл именно по нему
- Описывает ЧТО делает скилл и КОГДА его использовать
- Писать на языке, понятном агенту/проекту (например, по-русски, если проект и правила агента на русском)
- Пример хорошего описания: «Прогон PHPCS и PHPStan по изменённым файлам ветки через docker-контейнер dockerforjivo-php8.3-1. git — на хосте, проверки — в контейнере.»

## Как агент видит скилл

Список доступных скиллов подставляется в описание инструмента `skill`:

```xml
<available_skills>
  <skill>
    <name>php-code-quality</name>
    <description>Прогон PHPCS и PHPStan по изменённым файлам ветки... </description>
  </skill>
</available_skills>
```

Загрузка: `skill({ name: "php-code-quality" })`.

## Структура содержимого и длина

- Скилл подгружается **целиком** в контекст → `SKILL.md` держать коротким и по делу.
- Основной сценарий — сразу в `SKILL.md`; пошагово, с готовыми командами.
- **Аварийные/вспомогательные сценарии выносить в отдельные файлы рядом** в папке скилла
  (например `troubleshooting.md`, `container-recovery.md`, `reference.md`).
  В `SKILL.md` оставить одну строку-ссылку: «если <симптом> — читать `файл.md`».
  Так агент не спотыкается о лишний контекст в обычном потоке, но находит детали через `Read`, когда нужно.
- Если есть код/скрипты — класть их в подпапку скилла (например `scripts/`) и ссылаться на них.
- Описывать типичные проблемы и их признаки (симптом → причина → решение) — но в отдельных файлах, не в основном.

## Практический чек-лист (из опыта)

1. Придумать короткое понятное имя (см. regex выше).
2. Создать папку и `SKILL.md` с frontmatter.
3. В `description` — зачем скилл и когда применять.
4. Основной workflow — лаконично, команды готовые к запуску.
5. Редкие сценарии/восстановление после сбоев — отдельный файл в той же папке + ссылка из `SKILL.md`.
6. Прогнать реальный сценарий и дописать найденные подводные камни.
7. Проверить валидность: имя == папке, `SKILL.md` капсом, frontmatter на месте.

## Permissions (опционально)

Управление доступом к скиллам через паттерны в `opencode.json`:

```json
{
  "permission": {
    "skill": {
      "*": "allow",
      "pr-review": "allow",
      "internal-*": "deny",
      "experimental-*": "ask"
    }
  }
}
```

Поведение: `allow` — грузится сразу, `deny` — скрыт от агента, `ask` — запрос подтверждения.
Паттерны поддерживают wildcards (`internal-*`). Можно переопределять per-agent
(в frontmatter агента или в `opencode.json` → `agent.<name>.permission.skill`).

Полное отключение инструмента скиллов: `tools.skill: false` (тогда секция available_skills исчезает).

## Troubleshooting: скилл не появляется

1. Проверить, что файл называется `SKILL.md` (все капсом).
2. Проверить, что в frontmatter есть `name` и `description`.
3. Имена скиллов должны быть уникальны во всех папках.
4. Проверить permissions — скиллы с `deny` скрыты.
