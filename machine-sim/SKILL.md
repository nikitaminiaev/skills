# machine-sim

Суть «по-честному»: **геометрия → CAD-проверка (`cad-assembly-check`),
допуски → Монте-Карло, жёсткость → МКЭ, G-код → LinuxCNC, безопасность →
HAL-цепочка, контакты → MuJoCo.**

**Граница честности.** Физический движок не заменяет Монте-Карло и МКЭ в
допускной задаче. Зазор 0,1 мм и меньше лёгкие движки (Bullet/ODE/Gazebo) не
считают вовсе — «на перекос». MuJoCo считается лучше, но и он требует
калибровки: наивная сцена при зазоре 0,26 мм дала **0,25 мм проникновения**.
Поэтому MuJoCo допускается только после калибровочного сценария (посадка в
номинал ±0,05 мм, проникновение ≤ 0,03 мм). Не выполнилось — вопрос остаётся за
Монте-Карло и купоном.

## Что чем проверяется

| Задача | Инструмент | Где живёт |
|---|---|---|
| Посадки/интерференции/несущие контакты | build123d + `build/portal_check.py` | проект |
| Накопление ошибки по цепочке стыков | Монте-Карло, numpy: линейная 2D-модель + жёсткий 2D-«мост» для балки | `sim/stackup_mc.py` |
| Жёсткость рамы | аналитика балки (перекрёстная проверка) + МКЭ (scikit-fem) | `sim/stiffness.py` |
| G-код: синтаксис, лимиты, модальные группы | `rs274 -i <ini> <file>` | `linuxcnc-uspace` |
| Полный прогон машины | LinuxCNC + vismach под собственным `Xvfb` | `sim/linuxcnc/` |
| Контакты, удержание, усадка | MuJoCo (после калибровки) | `sim/mujoco/` |
| Единая точка проверки | `verify.py`: exit 0/1, логи в `build/logs/` | корень проекта |
| «Не идёт сигнал — всё стоп» | `estop_latch` + `watchdog` + `iocontrol.0.emc-enable-in` | `.hal` проекта |
| Платы / прошивка | KiCad CLI, ngspice / PlatformIO `native` | этап C |

## Единая точка проверки — `verify.py`

Стадии последовательно, exit 0/1, логи в `build/logs/`, фиксированные зёрна
(детерминизм). Агент чинит проект в цикле «правка → verify → снова» до PASS.
Стадия должна падать объяснимо (почему FAIL), а не «тихо PASS».

## Монте-Карло накопления ошибки

```bash
cd .../портальный_репликатор
/home/nikita/Документы/gtd/.venv/bin/python sim/stackup_mc.py --n 20000 --seed 1
```

- Модель: трансляции (x, y); цапфы в центре ячеек, разворот на поступательный
  результат не влияет (балка — исключение, решается точно из двух опор).
- Константы — **только** из `params.py` проекта (`seat_capture()`, зазор
  пояска, `SEAT_GAP`). Устаревшие `PIN_*`/`SOCK_CLEAR` протухли при редизайне
  коннектора: читать `params.py` заново, не реконструировать по памяти.
- Смотрим: `fail_rate` (доля несобранных итераций — главное), `err_p95_mm`,
  `per_interface_fail` (где ломается).
- Ablation обязателен: «без раструба (цилиндр)» / «без фиксации» / «как в
  проекте» — это и есть доказательство, что ошибка не накапливается.
- Проверять при грубой печати `--sigma-mfg 0.2`: устойчивость важнее номинала.

## МКЭ жёсткости

```bash
sudo apt install gmsh
pip install scikit-fem
```

- Нагрузка: собственный вес + каретка + захват. PLA: E ≈ 2,5–3,5 ГПа,
  текучесть ≈ 50–60 МПа (по Z печатные слои мягче).
- Аналитика Эйлера–Бернулли — обязательная перекрёстная проверка, иначе МКЭ
  может «врать молча».
- API: структурированная сетка `MeshHex.init_tensor` (gmsh не нужен);
  `Basis(m, ElementVector(ElementHex1()))`, `sym_grad`/`ddot` из
  `skfem.helpers`; `basis.doflocs` — (dim, ndofs), `basis.nodal_dofs` —
  (dim, nnodes). Шарнирная опора = фиксировать только Z
  (`basis.nodal_dofs[2][mask]`) плюс X/Y в одной точке, иначе МКЭ жёстче
  аналитики и проверка не сходится.

## LinuxCNC: G-код и машина

```bash
sudo apt install linuxcnc-uspace     # ~25 МБ, тянет PyQt5/opencv
linuxcnc machine.ini                 # GUI (AXIS)
```

### Headless-прогон

```bash
halrun -U >/dev/null 2>&1            # иначе rmmod/unloadrt failed
pkill -f rtapi_app
Xvfb :71 -screen 0 1280x1024x24 &
DISPLAY=:71 linuxcnc machine.ini program.ngc >>run.log 2>&1 &
```

- `xvfb-run` **не годится**: AXIS не подключается к `:99`.
- `pkill -f "<строка>"` убивает собственную оболочку, если строка есть в её
  командной строке. Безопасно: `pkill -f "pattern[.]"` или по PID.
- Последовательность: E-stop reset → `halui.machine.on` → `halui.home-all` →
  `halui.mode.auto` → `halui.program.run`. Имена пинов через дефис:
  `halui.program.is-running`, `is-idle`.

### HAL: проверенные ловушки

- `watchdog`: **не** принимает `names=` (только `num_inputs=N`, имя всегда
  `watchdog`); функции `watchdog.process` / `watchdog.set-timeouts`.
- `watchdog.enable-in` должен быть **1**, иначе `ok-out` принудительно 0.
  После срабатывания мониторинг перезапускается только переходом 0→1.
- `siggen`: функция `hb.update`, выход — `hb.clock` (bit), не `hb.out`.
- `estop_latch`: начальное состояние **Faulted**; в OK переходит только по
  переходу `reset` 0→1 при `fault-in=0` и `ok-in=1`.
- `setp` **не работает** на пины, подключённые к сигналу. Логику — в
  userspace-компонент (Python + `python3-hal`), наружу отдельный выход.
- `loadusr -Wn <имя>` должно совпадать с `hal.component("...")`, а не с именем
  файла.
- **У сигнала HAL ровно один источник.** Кнопка панели и скрипт авто-пуска не
  могут оба писать в `halui.machine.on`. Решение — компонент-«оператор»:
  входы `ui-*` и `script-*`, выходы `*-out = ui or script`. Побочный эффект:
  после подключения кнопок `halcmd setp halui.*` перестаёт работать — все
  скрипты жмут `script-*`.
- **Кнопка «Reset» в AXIS не снимает HAL-защёлку** `estop_latch`: AXIS сбрасывает
  задачу по NML, а `iocontrol.0.emc-enable-in=0` держит машину в E-stop, и в AXIS
  серые ВСЕ кнопки. Нужен свой импульс `estop.reset` (pyvcp или пин компонента).
- **Панель pyvcp**: `[DISPLAY] PYVCP = panel.xml` + `PYVCP_POSITION = BOTTOM`;
  пины появляются только после старта GUI, поэтому связи — в
  `[HAL] POSTGUI_HALFILE`, иначе «pin does not exist». Ширина панели задаёт
  минимальную ширину AXIS — кнопки не шире ~12 символов.

### G-код

- `M62/M63 P0` — **синхронно с движением**; `M64/M65 P0` — **немедленно**.
  Интерпретатор читает программу вперёд, поэтому с `M64` «взять деталь»
  срабатывает на середине подъезда, и сборка берёт не то. Для любого
  дискретного действия по позиции — только `M62/M63`. Признак: промахи кратны
  не времени, а шагу программы (легко спутать с «взял не ту деталь»).
- Внешние `M100..M199` капризны; analog — `M67/M68`.
- **Вложенные скобки в комментариях** `( ... (руки) ... )` дают
  `Nested comment found` и прерывают интерпретацию.
- `rs274 -i <ini> <file>` — headless-проверка (внешние M-коды не знает, это норма).
- **Программа встала на середине** → смотреть `pos-fb` последней оси: равен
  координате операции = soft limit. Проверять **все** точки плана, включая
  склад: `jy` = `y − смещение колонны`, лимит по Y действует и на складе.
- Лог программы может быть пустым: диагностику писать в свой файл.

### vismach

- `AsciiOBJ`/display lists под Xvfb падают (`glNewList` → GLError 1282):
  для симуляции — примитивы (`BoxCentered`, `CylinderZ`) по габаритам из CAD.
- `Capture()` обязан быть в дереве модели, иначе `invert()` падает на пустой
  матрице.
- Сбой в `traverse()` GUI проглатывает молча: оборачивать в `try/except` и
  писать `traceback` в файл.
- **Частота кадров ≠ частота событий.** `traverse()` ~5 Гц; за 0,2 с при
  15 мм/с каретка проезжает 3 мм, и «попадание в 0,5 мм» ловится как промах.
  Фронт выхода и положения осей фиксировать в отдельном потоке с шагом ~2 мс
  (очередь событий), кадр пусть только рисует. Признак: ошибки тем больше, чем
  быстрее подача.
- Результат писать **на каждое** изменение состояния, а не в конце: при
  падении иначе не видно, где остановилось.

### Телескопическая ось без второго джойнта

Пассивная нижняя ступень описывается одной функцией от `joint.*.pos-fb`:
`ext = clamp(-jz, 0, EXT)`, `part_z = A + jz - ext`. Держать её в одном месте
(`params.py`), иначе 3D-вид, план и проверка досягаемости разойдутся.

## MuJoCo: физический двойник

```bash
pip install mujoco            # 4.0.0, CPU достаточно
python -c "import mujoco; print(mujoco.__version__)"
```

Замер на паре «плита с цапфой — плита с чашкой» (2 тела, 18 геомов):
**37–48 тыс. шагов/с**, результат **детерминирован**. Полный прогон 22 деталей
при шаге 0,5 мс — минуты, не часы.

### Чего в MuJoCo нет

1. **Примитива «конус» нет** (`type="cone"` → `XML Error: invalid keyword`).
   Цапфа — усечённый конус выпуклым мешем или цилиндр + сфера.
2. **Вогнутую чашку одним телом не сделать**: «плита с отверстием» — сплошной
   `box`, цапфа ляжет на его верх. Чашка = кольцо (диск внутренней кромки) +
   поясок (пластины по окружности) + раструб (наклонные боксы) либо SDF-плагин.
3. **Контакты мягкие**: проникновение конечно. Шаг 0,2–0,5 мс и подбор
   `solref`/`solimp`; критерий проникновения ≤ 0,03 мм (12 % зазора 0,26 мм).

### Порядок (не переставлять)

1. **Калибровка**: цапфа падает в чашку без смещения → номинал ±0,05 мм,
   проникновение ≤ 0,03 мм. Пока не выполнено — двойник измеряет свои артефакты.
2. **Сетка**: смещение 0…4 мм, наклон 0…3°, μ 0,2/0,35/0,5, скорость подвода →
   карта PASS/FAIL и пиковая сила вставки.
3. **Полный план** из `build_plan.json`, теми же подачами, что в G-коде.

### Модель

- Динамика только у собираемых деталей; станина и витамины статичны.
- Отверстия, не участвующие в посадке, не моделировать (массу сохранить);
  упрощения фиксировать в отчёте.
- Масса: объём × 1,24 г/см³ (PLA), инерция от бокса.
- Трение PLA по PLA неизвестно (0,2–0,5): результат — карта по μ, в приёмку
  μ = 0,35 с проверкой краёв.
- Губки — две жёсткие щёки на приводе с трением; «приварить» деталь нельзя,
  иначе не поймать выскальзывание.
- Отчёт — один самодостаточный HTML (three.js вшит, как в `cad-demo`):
  таймлайн, график сил, таблица PASS/FAIL. Солвер в браузере не нужен.

## Ловушки

### MuJoCo (замерено на полном двойнике, 4.0.0)

- **`contype` статики в рантайме не включается.** MuJoCo 4.0.0 строит список
  пар-кандидатов коллизий при компиляции: выключить флаг можно, включить
  молча — нет (контактов не появится). Надёжный механизм «поставить деталь
  позже» — **mocap-парковка**: тело-«поздние детали» стартует в 2 м ниже
  стола (вне сцены), `install_late_parts()` телепортирует mocap-позой на
  место — геометры входят в коллизии сразу.
- **Витамины «в коридоре» вешают оси на упоре.** Статичная деталь, которая по
  техпроцессу ставится в конце (рельс, стойка портала копии), но с нуля лежит
  в сцене, цепляет переносимую деталь — ось стоит на упоре актуатора
  (замер: 8 контактов × 6,25 Н = 50 Н при jy≈30). Симптом: `ЗАСТОЙ` с
  `F=50 Н` и `dist≈0` — упор «в натяг», по глубине проникновения не виден.
  Дампить надо **силу** (`mj_contactForce` в массив `[6,1]`, объекта
  `MjContactForce` в Python API нет), а не только `dist`.
- **Мери отклонение поштучно/послойно, не максимумом.** Сборочный прогон
  «в среднем в допуске» — враньё: у стопки деталей с последовательной
  посадкой (шаг + зазор шарнира) ошибка считается от предыдущей и растёт
  с номером слоя — верхние слои выходят за допуск, когда «макс по
  прогоду» ещё зелёный. Пиши в лог dev каждой операции; ищи тренд, а не
  пик. Диагностика природы: повтори при другом μ — **одинаковый тренд при
  разных μ значит геометрия/кинематика, а не солвер и не трение**; лечить
  надо вычитающим элементом (направляющая на длине, телескоп), а не
  подкруткой контактных параметров.
- **Заморозка вскрывает скрытые интерференции — это ценность, а не поломка.**
  Пока деталь динамическая, движок «расталкивает»/уступает: складская деталь
  в 0,9 мм от прохода каретки молча переживёт десятки прогонов. Заморозил —
  ось встала на упоре. Диагностика застоя: дамп контактов с именами geom +
  `geom_xpos` (мировые координаты) — препятствие называется за один прогон.
  Проходи планом коридоры движения (маховики порталов, вылеты губок) против
  ВСЕХ складских поз статикой до первого сима.
- **Weld-заморозка склада — рабочий приём для сборочных двойников.** Пока
  деталь не тронута инструментом, держи её `<weld body1="world">` (активным),
  снимай равенство строго ПОСЛЕ активации хвата (сначала приварил к
  инструменту, потом отпустил со склада — деталь никогда не свободна).
  Замер: дрейф плиты 0,316 мм/2 с → 0,0003 мм. Не замораживай поставленные
  детали — иначе критерий удержания подделан.
- **SDF–SDF — главный тормоз.** Дефолт `sdf_initpoints=40/iterations=10`
  даёт ~30 шагов/с. Фильтр пар плита×плита + `8/4` → ~150 шагов/с при том же
  проникновении покоя (0,0075 против 0,0073 мм). Планируй бюджет: ~590 с wall
  на одну операцию переноса-посадки на сцене 29 тел/271 геомет.
- **Мини-сцена без фильтров основной сцены — источник ложных выводов.**
  Вылепил упрощённую сцену (полка + плита), забыл применить пост-обработку
  contype/conaffinity из `build_scene` — геометры не коллидируют, плита
  «стабильна» (на деле проваливается сквозь всё). Прежде чем делать вывод из
  редьюсд-сцены, проверь `mj_forward` после компиляции: `dist` контактов
  порядка нулю и `ncon > 0` там, где тела стоят друг на друге.
- **Медленная ползучесть стека при нулевом уклоне — обычными средствами не
  лечится; сначала диагностируй.** Дамп `mj_contactForce` + `contact.frame`:
  нормали строго вертикальны, боковые силы — только трение (тормозит, а не
  толкает), т.е. это не «склон». Мерзко срабатывает всё: демпфирование
  free-joint ×10 гасит дрейф лишь вдвое (0,88→0,43 мм/12 с), октодерево SDF
  мельче в 2 раза — на 13 %, а `opt.noslip_iterations = 3` (каноническое
  средство от ползучести) — вообще ничуть (0,907 против 0,878). Не трать
  итерации вслепую: мери скорость тел и делай freeze-тест (обнулить qvel,
  продолжить) — постоянная сила или расходится переходный процесс.
- **Settle/giveup — по симулированному времени, не по wall.** Жёсткий колпак
  на перемещение (30 с сим); при медленных стенных часах детерминизм и
  сходимость ломаются, если ждать секундами стенных часов.
- **Губки: фантомный натяг + weld.** Реальный натяг губок (1,8 мм) моделировать
  геометрией нельзя; держим weld-равенством, массы в актуаторах
  (`gravity_loads` + `held`) — иначе не поймать выскальзывание и вес.
- `geom_bodyid` — numpy-массив: индекс тела только через `int(...)`;
  bool/numpy-типы не сериализуются в `json` (касти `bool()`/`float()`).
- **Меряй dev от ФАКТИЧЕСКОЙ посадки, а не от командной цели, и своди их.**
  Цель `dev` = командный `axis_place`; «хак отпускания» (+0,5 мм к цели,
  чтобы деталь дотёрлась до упора) смещает и меру: физическая посадка и
  командная цель должны сходиться, иначе geometry-sрез 0,25 + хак 0,5
  дают «отклонение» 0,751 при стоящей в номинале детали. Симптом — dev с
  «половинчатыми» числами (0,25/0,5/0,75) ровно кратными хакам.
- **mocap-телепорт поздних витаминов вешай на тайминг операций, а не на
  момент «plan дошёл».** Рельс/Y-деталь телепортируй, когда снят перекрывающий
  склад (grip ступени), блок/винт — когда каретка на uplift ушла из
  габарита детали (замер: низ носителя каретки 107,84 — ровно низ блока).
  Ранний телепорт — пен в склад (run: 9,5 мм), поздний/сверхранний — пен в
  каретку. Признак: страж срабатывает на ВТОРОМ телепорте той же зоны.
- **Зеркальную геометрию вычитай, а не складывай: транскрипция знака —
  дорогая грабля.** Вилка с каналом = два рога ±(sy−щель)/2; записал дальний
  рог `(sy+2,8)/2` вместо `(sy−2,8)/2` — канал перекрыт, телепорт винта
  даёт 4,22 мм/700 Н на последней операции после минут зелёных деталей.
  Дамп контактных пар с именами и `geom_pos` при первом срабатывании стража
  (обёртка `_sample`, не менять физику) называет виновника за один прогон.

### Прочее

- **Три описания одной машины всегда расходятся.** Координаты в 3D-виде,
  генераторе программы и проверке → через неделю врут по-разному. Вынести в
  один модуль (`sim/.../geom.py`: боксы мира/склада/машины/деталей + проверки +
  `--json`), остальные только импортируют. Стадия геометрии стоит 0,1 с и ловит
  ошибки до долгого CAD-булеана.
- **Проверку «висит в воздухе» декларировать, а не ослаблять.** Подвешенная
  деталь (нижняя ступень телескопа) легальна, но список должен быть явным
  (`HANGING = {"z_stage2"}`) и с причиной, иначе проверка однажды «пассит» всё.
- Скользящие контакты (шина на рельсе): перекрытие во всём ходе + зазор
  +V/GND/сигнал (аналитика + Монте-Карло), просадка (ngspice), обрыв→стоп
  (HAL). Окисление/ЭМС/вибрация — только физические замеры, честная граница.
- «Coupon → факт»: тест-плита → размер/усилие → поправка зазора (у коннектора
  зазор растёт через `female_features(clear=...)`, высота стыка не меняется) →
  всё через `verify.py`.
- Проекты-симуляции в git: `out/` (STL/STEP/PNG) не коммитить.
- Запуск пустой GUI под Xvfb с `timeout` и «молчаливым» логом — норма.
