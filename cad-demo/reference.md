# Формат данных демонстрации

Справочник по тому, что лежит внутри `demo.html`. Нужен, когда правишь вьюер, пишешь свой экспортёр или разбираешь чужой файл.

## Общая картина

`demo.html` — это четыре JSON-блока, один бинарный блок и три скрипта:

```html
<script id="manifest" type="application/json">  геометрия: детали, цвета, смещения
<script id="frames"   type="application/json">  кадры: время + позы деталей
<script id="info"     type="application/json">  заголовок, фазы, проверки, параметры
<script id="bin"      type="application/octet-stream">  base64: вершины/нормали/индексы
<script>  three.js  </script>
<script>  OrbitControls  </script>
<script>  вьюер  </script>
```

Всё, что нужно для показа, лежит в файле. Внешних запросов нет.

## manifest

```json
{
  "order": ["cubeA", "cubeB", "tongueA"],
  "parts": {
    "cubeA": {
      "label": "Корпус A",
      "group": "A",
      "color": "#9aa3ad",
      "nv": 12345,
      "nt": 24000,
      "off_pos": 0,
      "off_nrm": 74070,
      "off_idx": 111105,
      "lo": [-15.0, -15.0, -15.0],
      "scale": [0.000458, 0.000458, 0.000458],
      "volume_mm3": 8421.5,
      "rest": {"p": [0, 0, 0], "q": [0, 0, 0, 1]}
    }
  }
}
```

| Поле | Смысл |
|---|---|
| `nv`, `nt` | число вершин и треугольников |
| `off_pos`, `off_nrm`, `off_idx` | смещения в `bin`, **в байтах** |
| `lo` | мировой минимум bbox детали (начала квантования) |
| `scale` | шаг квантования по осям: `мм = lo + q * scale` |
| `volume_mm3` | объём, для отчёта и проверки «та ли деталь» |
| `rest` | поза при `t=0`, если деталь уже сдвинута (необязательно) |

Геометрия **запечена в мировых координатах при `t=0`**. Дальше вьюер двигает деталь целиком матрицей, а не пересчитывает вершины.

## bin

Три массива подряд, все little-endian:

| Массив | Тип | Размер | Квантование |
|---|---|---|---|
| позиции | `int16` × 3 × `nv` | 6·nv байт | `q = (p − lo) / scale`, хранится как `q − 32768` |
| нормали | `int8` × 3 × `nv` | 3·nv байт | `n * 127` |
| индексы | `uint32` × 3 × `nt` | 12·nt байт | локальные, 0..nv−1 |

Между нормалями и индексами — выравнивание до 4 байт (нули).

Почему int16: при габарите 100 мм шаг квантования 1,5 мкм — глаз не видит. Экономия против float32 — в 2 раза по позициям и в 4 по нормалям.

Почему индексы uint32: деталь со сглаживанием легко переваливает за 65 535 вершин.

## frames

```json
{
  "t": [0.0, 0.1, 0.2, ...],
  "parts": {
    "cubeB": {
      "p": [[0,0,60], [0,0,59.7], ...],
      "q": [[0,0,0,1], [0,0,0,1], ...]
    }
  }
}
```

- `t` — общая сетка времени в секундах, возрастает.
- `p` — позиция в мм, `q` — кватернион `(x, y, z, w)`.
- У детали может быть своя сетка `parts[name].t`, если кадры неравномерные (например, щелчок за 0,02 с).
- Детали без записи в `parts` стоят на месте.
- Поза **абсолютная**: вьюер считает `M(t) · M(0)⁻¹` и применяет к запечённой геометрии. Поэтому экспортёр обязан положить `rest` = поза из первого кадра, иначе поза применится дважды.

Зачем запекать кадры, а не анимировать в JS: позы считает модель (там же, где кинематика), поэтому демо не может разойтись с расчётом. Плюс запекание умеет то, чего не умеет transform-анимация — деформацию (изгиб язычка, прогиб балки): вершины можно двигать морфом, кадр всё равно остаётся массивом чисел.

## info

```json
{
  "title": "Цикл стыковки кубиков",
  "subtitle": "кубик 30 мм, защёлка с бородкой",
  "duration": 12.0,
  "phases": [{"t0": 0, "t1": 2.5, "name": "1. Подвод", "note": "..."}],
  "checks": [{"name": "F входа", "value": "0,9 Н", "ok": true}],
  "params": {"Габарит": "30×30×30 мм"}
}
```

`phases` подсвечиваются по текущему времени; `checks` — таблица вердиктов, `ok: false` горит красным. `params` — произвольные пары «подпись → значение».

## Вьюер

Один IIFE, без сборки. Что внутри:

| Блок | Ответственность |
|---|---|
| декод `bin` | `DataView` → `Float32Array` → `BufferGeometry` |
| сцена | свет (полусферный + 3 направленных), сетка 240 мм, фон из CSS-переменной `--bg` |
| камера | перспектива 38°, `OrbitControls`, `fit(dir)` по bbox |
| кадры | линейный поиск сегмента, `lerp` позиции, `slerp` кватерниона |
| разрез | `THREE.Plane` + `material.clippingPlanes`, слайдер по оси |
| UI | кнопки, таймлайн, фазы, легенда |
| тема | `prefers-color-scheme` + слушатель смены |

Материал — `MeshStandardMaterial`, `side: DoubleSide` (иначе разрез показывает пустоту), `metalness 0.15`, `roughness 0.62`.

## Разбор эталонного файла

`Карусель_цикл_смены_иглы.html` (1,7 МБ, сделан вручную под конкретный механизм) — откуда взят формат:

| Что | Как сделано | Что взято в скилл |
|---|---|---|
| Геометрия | `#manifest` + `#bin`, квантованные int16 | да, один в один |
| Кадры | `#frames`, время + позы | да |
| Отчёт | `#info`, параметры и вердикты | да |
| three.js | вшит в `<script>` (603 КБ) | да, vendor-копия |
| UI | пуск, скорость, пресеты камеры, таймлайн, таблица фаз | да |
| Разрез | нет | **добавлен** (clip-плоскость) |
| Легенда с выключением деталей | нет | **добавлена** |
| Тёмная тема | есть | сохранена |

Ключевое отличие: у «Карусели» геометрия и кадры генерировались скриптом под один механизм. Здесь то же самое вынесено в универсальные `export_demo.py` + `build_demo.py`, а вьюер стал шаблоном.

## Ограничения текущей версии

| Чего нет | Как обойти |
|---|---|
| Морф-таргетов (деформация по кадрам) | пока двигать деталь целиком; для изгиба язычка — отдельная деталь с позой |
| Разреза только по мировым осям | для косого разреза поправить `applyClip()` |
| Меток и выносок в 3D | подписи в легенде + таблица фаз |
| Экспорта скриншота из UI | headless Chrome |
| Анимации материалов (прозрачность) | `opacity` в manifest — статично |

Если понадобится морф — добавлять в `frames` массив смещений вершин и `morphAttributes` в геометрию. Формат это выдержит: кадр уже массив чисел.
