# cad-demo

Демонстрация концепции — это **один HTML-файл**, который открывается двойным щелчком, работает без интернета и показывает геометрию **из той же CAD-модели**, что и чертёж.

Не «красивая картинка», а **интерактивный отчёт**: геометрия, движение, фазы, числа проверок.

## Когда использовать

- Нужно показать, как работает механизм (защёлка, стык, редуктор, захват).
- Нужно объяснить концепцию человеку, который не будет читать CAD.
- Нужно сравнить два варианта геометрии.
- Нужно показать, что сборка проходит проверки — с числами, а не словами.

**Не использовать** для: быстрой проверки гипотезы (там хватит картинки из `visual_review.py`), отчёта о замерах (это `results.csv` + markdown).

## Твёрдые правила

1. **Геометрия только из CAD.** Никаких кубов, нарисованных руками в JS. Если деталь есть в демо — она из `build_parts()`.
2. **Один файл.** `three.js` и `OrbitControls` вшиты в HTML. Никаких CDN, `import` с URL, внешних текстур и шрифтов.
3. **Офлайн.** Открыл в самолёте — работает.
4. **Размер ≤ 4 МБ.** Обычно 0,6–1,5 МБ. Больше — уменьшай тесселяцию или число кадров.
5. **Числа настоящие.** Таблица проверок берётся из `check_*.py`, а не пишется от руки. Если проверка не пройдена — в демо горит красным.
6. **Кадры запекаются в Python.** Не анимируй в JS тем, что должно быть посчитано: позы, деформации, траектории считает модель.
7. **Язык — русский**, подписи и фазы тоже.
8. **mp4/gif из matplotlib — не демонстрация.** Это отладочный рендер для себя. Людям — HTML.

## Как это работает

```
CAD (build123d)
   │  build_parts() -> {имя: Shape}
   ▼
export_demo.py  ──►  model.json     геометрия (квантованный bin) + кадры + info
   │
   ▼
build_demo.py   ──►  demo.html      один файл: three.js + данные + вьюер
```

### Шаг 1. В модуле сборки описать демо

Модуль (`gen_latch.py` или рядом `demo_latch.py`) дополнительно к `build_parts()`:

```python
DEMO = {
    "title": "Цикл стыковки кубиков",
    "subtitle": "кубик 30 мм, защёлка с бородкой",
    "duration": 12.0,
    "colors": {"cubeA": "#9aa3ad", "cubeB": "#c9a227", "tongue": "#2a9d8f"},
    "labels": {"cubeA": "Кубик A", "cubeB": "Кубик B", "tongue": "Язычок"},
    "params": {"Габарит": "30×30×30 мм", "F входа": "0,9 Н"},
    "checks": [{"name": "F входа", "value": "0,9 Н", "ok": True}],
    "phases": [
        {"t0": 0.0,  "t1": 2.5, "name": "1. Подвод",   "note": "промах 2 мм, воронка ловит"},
        {"t0": 2.5,  "t1": 6.0, "name": "2. Защёлка",  "note": "бородка уходит и щёлкает"},
    ],
}

def demo_frames():
    """Запечённые кадры. Позы абсолютные, в мм и кватернионах (x,y,z,w)."""
    t = [i * 0.1 for i in range(121)]
    return {"t": t, "parts": {"cubeB": {"p": [...], "q": [...]}}}
```

Если деталь при `t=0` уже сдвинута — вернуть `demo_rest()` с её позой, иначе вьюер посчитает её за начало координат. Для деталей с кадрами `rest` экспортёр выводит сам из первого кадра, вручную его задавать не нужно.

### Параметры в адресной строке

Демо можно открыть сразу на нужном кадре — удобно для ссылок и для проверки скриншотом:

```
demo.html#t=3.5          начать с 3,5 с
demo.html#panel=1        сразу открыть панель проверок
demo.html#clip=z         включить разрез по Z
demo.html#cam=top        камера сверху
demo.html#play=1         автозапуск
```

Параметры складываются: `#t=6&panel=1&cam=side&clip=y`.

### Шаг 2. Экспорт и сборка

```bash
VENV=/home/nikita/Документы/gtd/.venv/bin/python
SKILL=~/.config/opencode/skills/cad-demo/scripts

$VENV $SKILL/export_demo.py path/to/gen_latch.py -o _resurses/demo/model.json
$VENV $SKILL/build_demo.py _resurses/demo/model.json -o _resurses/demo/latch.html
```

### Шаг 3. Проверить, что реально рисуется

```bash
google-chrome --headless=new --no-sandbox --disable-gpu --enable-unsafe-swiftshader \
  --screenshot=/tmp/shot.png --window-size=1280,800 --virtual-time-budget=4000 \
  file://$PWD/_resurses/demo/latch.html
```

Посмотреть скриншот глазами (read tool). Пустая сцена, чёрный экран, «Ошибка: …» — демо не готово.

## Что умеет вьюер (и чего требует от данных)

| Возможность | Как задаётся |
|---|---|
| Вращение/масштаб/сдвиг | OrbitControls, всегда |
| Пуск/пауза, скорость 0.1–2 | кнопки, `info.duration` |
| Таймлайн с перетаскиванием | `frames.t` |
| Таблица фаз с подписями | `info.phases` |
| Таблица проверок PASS/FAIL | `info.checks` |
| Параметры сборки | `info.params` |
| Легенда с включением/выключением деталей | `manifest.parts[*].label`, `.color` |
| Разрез плоскостью X/Y/Z и ± | кнопка «разрез» + слайдер |
| Пресеты камеры: изометрия/сверху/спереди/сбоку | всегда |
| Тёмная и светлая тема | `prefers-color-scheme` |

## Критерии качества

- [ ] Открывается без интернета (нет `http://` в файле).
- [ ] ≤ 4 МБ.
- [ ] На первом кадре видна вся сборка (камера «изометрия» ставится при старте).
- [ ] Все детали из `build_parts()`, ни одной нарисованной в JS.
- [ ] Каждая фаза имеет `name` и `note` — по ним человек понимает, что происходит.
- [ ] Проверки в таблице совпадают с реальным отчётом `check_*.py`.
- [ ] Скриншот в headless Chrome не пустой.
- [ ] Подписи по-русски, без англицизмов без расшифровки.

## Чего не делать

| Антипаттерн | Почему плохо |
|---|---|
| mp4/gif из matplotlib для людей | нельзя крутить, нет фаз, нет чисел, не видно изнутри |
| геометрия, нарисованная в JS | расходится с CAD, врёт |
| анимация `mesh.rotation.y += 0.01` | не связана с кинематикой, показывает несуществующее движение |
| проверки, вписанные руками | демо врёт в самом важном месте |
| внешний CDN с three.js | не работает офлайн, ломается через год |
| 100 МБ тесселяции | не открывается на ноутбуке |

## Файлы скилла

| Файл | Что |
|---|---|
| `templates/demo.html` | каркас вьюера с плейсхолдерами |
| `scripts/export_demo.py` | build123d → `model.json` (геометрия, кадры, info) |
| `scripts/build_demo.py` | `model.json` → один HTML, проверка размера и офлайна |
| `vendor/three.min.js` | three.js r130-ish, UMD-сборка (глобальный `THREE`) |
| `vendor/OrbitControls.js` | OrbitControls, глобальный `THREE.OrbitControls` |
| `reference.md` | формат данных, устройство вьюера, разбор эталонного файла |

Подробности формата — `reference.md`. Если меняешь шаблон — проверь его на синтетической модели (`/tmp`), а не на боевой сборке.
