# cad-assembly-check

Пять автоматических проверок, которые ловят «то, что глаза не видят» в 3D-сборке:
1. **INTERFERENCE** — никакие тела не должны пересекаться (кроме декларированных контактов-посадок).
2. **FITS** — фактические минимальные зазоры посадок против номинала (ловит сдвиг сетки, неверную высоту стека, «утопленную» деталь).
3. **SUPPORT** — заявленные несущие контакты реально касаются (ловит «висящую» деталь: зазор там, где должно быть опирание).
4. **LOCKS** — замок держит: при малом осевом сдвиге без доворота деталь упирается (ловит «лапка не в канавке», незащёлкнутый байонет/бурт).
5. **CHANNEL** — вдоль оси луча/жгута/вала не должно быть сплошных тел (ловит «заглушку» в световом канале, ногу на трассе).

Найдено и проверено на DLP-степпере (машиностроение/микро репликатор, `check_assembly.py`):
INTERFERENCE/FITS подряд выявили линзу, «тонущую» в соседней трубе; держатель, перекрывающий свет в верхних 4 мм;
сетку отверстий плиты, сдвинутую на половину плиты; шпильку в сплошной плите.
SUPPORT поймал оптическую колонну, которая «висела» без опоры (зазор 0.9 мм там, где заявлен контакт),
LOCKS — байонетные стыки v2 (труба/держатель/колено/прижим линзы).

## Когда использовать

- После создания или правки любой многотельной сборки (плиты + шпильки, оптика, корпуса).
- Перед тем как доверять компоновке и переходить к закупке/печати.
- Когда нужен воспроизводимый отчёт-артефакт (PASS/WARN/FAIL) для проекта.

## Контракт сборки (обязательно, без него проверки невозможны)

- Сборка раздаёт **`build_parts()` → `dict[name → Shape]`** в финальных мировых координатах (обычно
  рядом есть `build()` → `Compound` для экспорта).
- Сложный узел (объектив из конуса+цилиндра, радиатор из рёбер) — **`Compound` одной деталью**,
  иначе узел «сам с собой» даст ложное пересечение.
- Имена деталей стабильны: их использует конфиг (белый список контактов, посадки, прозрачные тела).

## Пять проверок (алгоритмы)

### 1. INTERFERENCE — pairwise-пересечения

```
для всех пар (a_i, a_j), i<j:
    если пара в ALLOWED:                    continue   # декларированный контакт/посадка
    если bbox не задевают с запасом ~2 мм:  continue   # предфильтр производительности
    inter = a - (a - b)                                 # объём пересечения (boolean, НЕ face-intersect!)
    if inter.volume > INT_TOL (~0.1 мм³):   FAIL
```

### 2. FITS — зазоры посадок

```
для каждой пары-посадки (a, b, номинал):
    d = BRepExtrema_DistShapeShape(a, b).Perform(); .Value()   # min дистанция
    if d < номинал - TIGHT:  WARN "тесно"
    if d > номинал + LOOSE:  WARN "болтается"
```

Каверза: min-дистанция возвращает `0` на **торцевых контактах** (деталь лежит на поверхности).
Мерить только **радиальные посадки без лицевого контакта** (вал в расточке, стекло в седле),
либо опускать тело чуть ниже, либо сверять щель по боковой поверхности.

### 3. SUPPORT — несущие контакты реально касаются

```
для каждой пары-опоры (a, b, мин_площадь):
    S = max по сдвигам a на ±0.15 мм по X/Y/Z ( объём(a_сдвинутое ∩ b) / 0.15 )
    if S < мин_площадь:  FAIL "нет опоры: <имя> висит"
```

Площадь контакта оценивается «сдвигом»: сдвигаем деталь на 0.15 мм к партнёру и
делим объём пересечения на сдвиг. Ловит ровно тот класс багов, что не видит
INTERFERENCE: деталь стоит там, где по чертежу должна опираться, но между ними
щель (перепутана высота стека, забыт бурт/пояс, деталь «уехала» на 1–2 мм).

### 4. LOCKS — замок держит без доворота

```
для каждого замка (верх, низ, сдвиг (dx,dy,dz), порог):
    V = объём( верх_сдвинутый ∩ низ );   V < порог  ->  FAIL "замок не собран?"
```

Реализация по-настоящему функциональна: для байонета/бурта сдвигаем верхнюю
деталь ВДОЛЬ оси снятия на 0.5 мм (без доворота). Если лапка в канавке — она
упирается в стенку, пересечение > порога, замок работает. Если лапка промахнулась
мимо канавки (или канавки нет) — сдвиг проходит свободно, FAIL. Хорошо ловит
«собрал, но не довернул», «шпоночный канал не совпал с лапкой», «лапка шире
канавки».

### 5. CHANNEL — трасса вдоль оси

```
зонд = Pos(x0, y0, (z1+z0)/2) * Cylinder(R_PROBE~0.4, z1-z0)   # тонкий цилиндр по оси
 для каждого тела вне TRANSPARENT (оптика/стекло/провод):
    if пересечение с зондом > 0.1 мм³:   FAIL "трассе мешает <имя>"
```

Ходит насквозь через пустотелые каналы (трубы, раструбы, окна) и не может «зацепить»
скрытую заглушку: если в световом/кабельном канале стоит глухой диск — пересечение будет.

## Вердикт и отчёт

- `fail > 0` → **FAIL** (exit code 1), только warn → **WARN**, иначе → **PASS**.
- Отчёт — в stdout + файл-артефакт (в проекте: куда принято, напр. `_resurses/check_report.txt`).
  Формат строк: `имя1 - имя2 : замерено мм (ждём номинал) [OK/WARN/FAIL]`.
- **Правило проекта**: после любого изменения геометрии прогони проверку — сборка должна остаться PASS.

## VISUAL — взгляд агента (другая модальность)

Числовые проверки не видят «деталь не та», «деталь висит», «тракт перекрыт ногой».
`scripts/visual_review.py` генерирует из `build_parts()` три листа (PNG, matplotlib Agg, без GPU):

- **сборка**: 4 изометрии + 3 ортографии (proj_type ortho) + изо с наложенной световой трассой;
- **штучный лист**: каждая деталь отдельной панелью, заголовок = `имя | Dx×Dy×Dz мм | объём мм³` — видно «не та деталь / не тот габарит»;
- **разрезы-clip**: убрана ближняя половина сборки + линии сечения trimesh — видны внутренности тракта (колено, зеркало, рукав, стек линз).

Дальше агент читает листы глазами (vision) и проходит чек-лист: стык входит в стык,
тракт виден глазом на разрезах, нет «висящих»/«утопленных» деталей, симметрия.

Каверза: painter's algorithm matplotlib недостоверен в глубине — **одна изометрия врёт**;
достоверны разрезы и штучный лист. Графики-артефакты складывать туда же, куда отчёт
(напр. `_resurses/preview/`).

## Реализация

1. Скопировать `scripts/assembly_check.py` (шаблон на build123d/OCP) в проект рядом со сборкой.
2. Скопировать `scripts/visual_review.py` (шаблон листов визуальной ревью) рядом;
   настроить в CONFIG только `GROUPS` (метка, цвет, подстроки имени), `LIGHT_POLYLINE`
   (совпадает с probe-check) и `CUTS` (секущие плоскости под нужные ракурсы).
3. Заполнить только `CONFIG` в шаблоне:
   - `ALLOWED` — пары, которые специально соприкасаются (гайка↔шпилька, плита↔стойка, линза↔седло);
   - `FITS` — посадки `(имя1, имя2, номинал_мм, комментарий)`;
   - `SUPPORT` — несущие контакты `(имя1, имя2, мин_площадь_мм², что это)` — всё, на чём что-то стоит;
   - `LOCKS` — замки `(верх, низ, (dx,dy,dz)_сдвиг_мм, что это)` — байонеты/бурты;
   - `CHANNEL` — `(x, y, z0, z1)` + `TRANSPARENT` — оптические/прозрачные тела.
4. Прогнать. Гнать при каждом изменении геометрии.

Для других CAD-ядер (FreeCAD, OpenSCAD, Parasolid) алгоритмы те же, но:
булево пересечение = `a - (a - b)` ядра, дистанция = min-дистанция ядра, «contains-точки» нет —
трассы делай зондом-цилиндром.

## OCP-грабли (кратко)

- `Cylinder`/`Box` **центрируются по всем осям** — позиционирование только `Pos(x,y,z) * shape`,
  высоты считать от «низа/верха», а не центра.
- `Shape.intersect()` — НЕ булево пересечение тел; настоящее = `a - (a - b)`.
- `Shape.contains(point)` отсутствует — только зондом.
- `BRepExtrema_DistShapeShape` — из `from OCP.BRepExtrema import ...` (OCP-прокси в build123d есть).
- Подробности и диагностика ложных срабатываний: см. `reference.md`.
