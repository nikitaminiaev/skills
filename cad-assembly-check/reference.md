# Reference: OCP/build123d-грабли и диагностика ложных срабатываний

Дополнение к SKILL.md. Читать когда проверка выдаёт непонятный FAIL/WARN или
синтаксическая реализация спотыкается об API.

## OCP / build123d — поведение, которое кусает

### Центрирование примитивов
`Cylinder(radius, height)` и `Box(l,w,h)` центрируются по ВСЕМ осям: `Cylinder(3, 160)`
занимает Z от -80 до +80, а не 0..160. Отсюда типичные баги сборки: «труба ниже на полдлины»,
«шпилька не достаёт», «стекло тонет в рамке».

Правило: `Pos(x, y, z) * shape`, где z считать по формуле «низ + height/2», держать в коде
список констант стека «низ/верх» каждой опорной детали с комментарием.

### Булево пересечение — не `intersect`
`a.intersect(b)` в build123d даёт пересечение ГРАНЕЙ (ShapeList), а не тела — объёма не будет.
Настоящий объём пересечения:

```python
def inter_volume(a, b):
    try:
        inter = a - (a - b)      # a минус (a минус b) = a ∩ b
    except Exception:
        return 0.0
    if inter is None:
        return 0.0
    try:
        return max(float(inter.volume), 0.0)
    except Exception:
        return 0.0
```

### Нет `contains(point)`
`Shape.contains()` в build123d 0.11 отсутствует. «Точка внутри тела?» — заменяем зондом:
тонкий цилиндр вдоль интересующей оси и булев объём с каждым телом.

### Минимум-дистанция и торцевые контакты
`BRepExtrema_DistShapeShape` возвращает 0, если тела соприкасаются ЛЮБОЙ поверхностью.
Шпилька, стоящая на плите, даёт 0 даже при зазоре 0.25 в отверстии. Ниже — как различать:

- зазор в отверстии: измерять пары БЕЗ лицевого контакта (телelong сквозной: шпилька сквозь плиту,
  вал в расточке, линза в седле);
- деталь «сидит на» другой: это контакт — для него только interference (объём = 0 ок).
- если нужно точно измерить боковую щель: опустить тело на 1 мм ниже (на время замера),
  сделать `Pos(0,0,-1) * shape`, измерить, вернуть обратно — номинал не меняет, контакт уходит.

### Bounding-box предфильтр
Булевы операции на BRep — дорогие. Перед боолем в огромной матрице пар:
```
if not перекрытие с запасом 2 мм: continue
```

### Композиты (Compound)
Булево с `Compound` работает (это одно топологическое тело-набор). Группируй узел
(объектив: конус+баррел+воротник+резьба) в `Compound(children=[...])` одной деталью —
попарная матрица не проверит «узел сам с собой».

### Повторный старый .stl
Правки в `gen_parts.py`/`assembly.py` не трогают ранее экспортированные STL.
После правки геометрии перегенерируй экспорт ДО запуска проверки, иначе проверяешь старьё.

## Диагностика ложных срабатываний

| Симптом | Причина | Решение |
|---|---|---|
| Деталь «в плите»/«утонула» на константную величину | координата считалась от центра примитива | перевести на «низ/верх» стека |
| Свет-трасса упёрлась в тело между зоной боpa и верхом | боре не сквозной (заканчивается раньше тела) | продолжить боре на всю деталь |
| dist = 0 при ожидаемом зазоре | лицевой контакт деталей | мерить только радиальные посадки / отпустить тело |
| Все пары «пересекаются» одинаково | рисунок сетки во «всемирных» координатах, а вычитание в локальных | перевести координаты отверстий в локальную систему ТЕЛА |
| Интерференция, но только после merge | вычитание делалось до позиционирования, а в сборке — после | вычитать в локальной системе, потом `Pos` |
| API менялось между версиями build123d | 0.11 `contains` нет, `intersect` не булев | смотреть reference по текущей версии, проверять smoke-тестом |

## Smoke-тест API (первый же прогон в новом окружении)

```python
import build123d as b
from OCP.BRepExtrema import BRepExtrema_DistShapeShape
a = b.Cylinder(5, 20)
x = a - (a - b.Pos(12, 0, 0) * b.Cylinder(3, 20))   # объём пересечения = 0
d = BRepExtrema_DistShapeShape(a.wrapped, b.Pos(12, 0, 0) * b.Cylinder(3, 20).wrapped)
d.Perform(); print(d.Value())                        # вблизи 7
```

Если OCP-импорт падает — сборка OCP-прокси отличается (см. версию build123d в проекте),
импорт строить из его провайдера.

## Рендер листов matplotlib (модальная ревью, visual_review.py)

- `Shape.tessellate(tol)` в build123d 0.11 возвращает вершины как `Vector`, не числа:
  перед trimesh/matplotlib нужен `np.array([(v.X, v.Y, v.Z) for v in verts])`.
- Параметр допуска в 0.11 не продирается к мешеру — на tol=0.1 и tol=8 выходит одна и та же
  сетка (~82k граней на всю сборку). Реальный размер сетки — только decimation:
  trimesh `simplify_quadric_decimation(face_count=N)` (нужен пакет `fast-simplification`).
- Для сечений trimesh (`mesh.section`) нужен `networkx`.
- `facecolors` Poly3DCollection принимает массив (N,4) — по цвету на грань; при погранной
  лемберт-заливке коэффициент яркости держать формой (N,1), иначе broadcasting (1,3)*(N,) падает.
- Painter's algorithm (нет z-буфера): тонкие длинные рёбра (шпильки) рисуются ок, но
  перекрывающиеся на луче грани дают артефакты («лохматость»). Верить в глубину — по
  clip-разрезам и штучному листу, не по одной изометрии. В zoom-листе рабочая проекция —
  вид сверху (концентричность болта в пазу/расточке видна без глубины), изо — для ориентации.
- Zoom-зоны: полуразмер бокса брать с запасом ~1.5× от детали (видны и деталь, и соседи).
  Отбор граней — ТОЛЬКО геометрической обрезкой бокса (Sutherland–Hodgman по 6 плоскостям,
  фан-триангуляция выпуклого результата): фильтр по центроиду — грабли, пойманы на
  DLP-степпере (дно плиты 250×250: центроид в зоне, вылезает на весь кадр «гигантскими
  треугольниками»). Кандидатов перед обрезкой отбирать по пересечению bbox грани с боксом.
  Пустая панель = зона мимо деталей: проверить центр.
- Освещение в листовом рендере не «волшебное» — чтобы не путать окраску по нормали
  (render_preview-style) с окраской по группе: красить строго по группе, свет — лемберт
  одним направлением.
## WebGL-viewer (render_views.py + view_template.html)

Проверено 2026-11-10, Chrome 156, Debian 13, без GPU.

- **Тесселяция.** `Shape.tessellate(tol)` в build123d 0.11 переиспользует уже
  готовую сетку: tol=0.05/0.2/0.6/2.0 дают одинаковые 100 треугольников на
  цилиндр. Реальный регулятор — угловой допуск. Перед съёмом чистить старую
  триангуляцию и мешить заново:
  `BRepTools.Clean_s(shp.wrapped)` → `BRepMesh_IncrementalMesh(wrapped, tol, False, ang, True)`.
  Замер на цилиндре: ang=0.5 → 500, 0.05 → 1004, 0.02 → 2512 треугольников;
  время — доли секунды. tol почти не влияет, ang — влияет.
- **Цвет.** three.js r2021 не включает color management: `new THREE.Color('#8899aa')`
  трактуется как линейный, а `outputEncoding = sRGBEncoding` + ACES выбеливает
  материал почти в белый. Лечится `new THREE.Color(hex).convertSRGBToLinear()`
  и `toneMappingExposure ≈ 1.0`.
- **Headless Chrome.** `--headless=new --disable-gpu --use-angle=swiftshader
  --no-sandbox --disable-dev-shm-usage --hide-scrollbars --force-device-scale-factor=1
  --window-size=W,H --virtual-time-budget=8000 --run-all-compositor-stages-before-draw
  --screenshot=out.png file:///…/view.html?shot=1`. В headless `webgl2=true`;
  кадр 600×400 — около 1 с, 2000×1400 — 2–5 с. `?shot=1` прячет панель UI
  (класс `body.shot`), оставляя линейку и подписи.
- **Модель в HTML.** Вершины/индексы — base64 от `Float32Array`/`Uint32Array`,
  один `BufferGeometry` на тело. 280 тел мелкой сеткой дают сотни МБ — для
  интерактивного файла брать `context_angular ≥ 0.6`, для PNG-зума мелкую
  сетку только выбранным телам (`--only`), контекст — грубо.
- **Врезка и оси** — второй проход `renderer.setViewport/setScissor` в тот же
  canvas. Объекты, которые должны быть видны только во врезке (рамка зума),
  класть на слой 1 и `insetCam.layers.enable(1)`: главная камера их не видит.
- **Clip-плоскость.** `THREE.Plane(normal, constant)`; при `normal = -axis`
  остаётся половина с координатой `< pos`. `flip` в CLI меняет знак нормали.
  `renderer.localClippingEnabled = true`, у материалов `clippingPlanes`.
- **Тени** — `ShadowMaterial` на полу (небо 0.16) + один directional с
  `PCFSoftShadowMap`; для ортокамеры `shadow.camera` подгонять под габарит,
  иначе тень обрезается.
- **Габарит и камера.** Ортокамера: `size` — вертикальное поле, ширина =
  `size × aspect`. `fit_view` берёт bbox выбранных тел × 1.25. Для зума на
  мелкий узел контекст оставлять призраком (`--ghost`), иначе соседние тела
  закрывают кадр.
- **Повторные виды.** Лист — это 6 кадров одной сцены; без кэша каждый кадр
  мешает все тела заново (280 тел — минуты). Кэш `(id(shape), angular)`
  в `render_views.py` + `--batch` (JSON-список видов) режут это до одного
  прохода тесселяции. Мелкая сетка (`--angular`) — только телам из `--only`;
  без `--only` весь кадр идёт по `--context-angular` (0.25 по умолчанию).
- **Скорость кадра.** 280 тел, 1600×1100, SwiftShader: ~30–60 с на кадр;
  из них заметная доля — `EdgesGeometry` и карта теней 2048². Если кадров
  много, сначала уменьшать `--context-angular` и разрешение, потом тени.
- **`--virtual-time-budget` — это не «сколько ждать загрузку».** Chrome крутит
  `requestAnimationFrame` в виртуальном времени: 8000 мс ≈ 480 полных кадров.
  Для 246 тел кадр ~0,5 с, то есть 4 минуты на один PNG. Ставить 400 мс
  (≈24 кадра): последний кадр остаётся на экране, скриншот снимается после
  бюджета. Если убрать `requestAnimationFrame` совсем, canvas выходит чёрным —
  композитор не успевает показать кадр.
